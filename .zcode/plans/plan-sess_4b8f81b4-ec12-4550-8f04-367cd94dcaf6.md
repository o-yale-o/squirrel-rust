# Squirrel 3.2 → Rust 复刻计划（仅 Windows）

## 一、可行性评估：**高度可行**

依据（来自对 D:\OpenSource\squirrel 的完整探索）：

- **规模可控**：全项目约 1.5 万行 C/C++。核心引擎 squirrel/ 共 11,570 行（sqvm 1811、sqapi 1631、sqcompiler 1636、sqbaselib 1404、其余为对象/状态/词法/表/类等），标准库 sqstdlib/ 2,871 行（含 666 行自包含正则引擎），独立解释器 sq.c 349 行。Rust 版预计 1.2～1.8 万行。
- **OS 依赖面极小**：核心引擎零 Win32 API，全部依赖是纯 CRT（stdio、time、getenv、system、rand），标准库用 Rust std 即可覆盖。
- **架构清晰、边界干净**：单遍递归下降编译器（无 AST）→ 61 条定长 8 字节指令 → 共享单栈 + CallInfo 帧窗口的寄存器式 VM；引擎是库、宿主是调用者的分层明确。
- **主要风险点及对策**（均已定位到具体代码）：
  1. **引用计数 + 仅回收环的辅助 GC**（MARK_FLAG 复用引用计数高位，侵入式双链）→ Rust 用 `Rc`/`Weak` + SharedState 侧注册表复刻语义，不写 unsafe；
  2. **goto 驱动的异常路径**（SQ_THROW → exception_trap）→ 重构为 `Result`/错误对象 + 帧退栈逻辑；
  3. **栈槽裸指针 + RelocateOuters 重定位**（C++ 因 realloc 不得不做的 hack）→ Rust 一律用索引，根除此类问题；
  4. **union 类型双关**（LOADFLOAT、sarg1 等）→ enum + `to_bits`/`from_bits` 集中封装；
  5. **foreach 顺序依赖哈希表物理布局** → SQTable（Lua4 风格开链）逐位复刻：哈希函数、节点结构、插入算法、rehash 时机、Next() 遍历顺序；
  6. **浮点/整数解析与格式化、错误消息文本**的细微差异 → 由差分测试暴露后逐个修正。

## 二、确认的决策

- **形态**：纯 Rust crate（安全 API）+ `sq.exe` 等价 CLI；不做 C ABI 兼容层。
- **宿主与引擎的交互模型**（回应你的疑惑）：引擎是 Rust 库（crate），任何 Rust 程序作为宿主通过**进程内类型安全 API** 使用它——Rust 调脚本用 `compile() + closure.call(args)`，脚本调 Rust 用 `register_global(name, rust_closure)` 注册 native 函数，数据以 `Value` 枚举/栈 API 交换。**不走文件、不走 IPC**；文件仅用于加载脚本源码与 .cnut 字节码。CLI（REPL）只是官方 sq.c 等价的"示例宿主"：循环 读 stdin 行 → compile → call → print，续行/`=` 改写等都是宿主侧逻辑。
- **保真度**：指令级对齐——编译器逐指令复刻（含窥孔优化），`.cnut` 字节码与官方 Win64 默认构建互通。
- **验证**：差分测试——本机编译原版 C++ sq.exe，同一语料双引擎执行，比对 stdout 与退出码。
- **配置基线**（对齐官方 Windows x64 默认构建）：`SQInteger = i64`（_SQ64）、`SQFloat = f32`、字符串为单字节（非 SQUNICODE、Latin-1 字节语义）；`.cnut` 头部 sizeof 标签为 1/8/4。

## 四、里程碑（每步带单测，M5 起持续跑差分）

- **M0 脚手架 + 差分骨架**：建 workspace；编译原版 sq.exe（CMake + MSVC 或 MinGW，实施时确认环境；若不可用则回退为"语料期望输出快照"）；写差分 runner；定义宿主 API 骨架（Vm/Value/错误类型）。
- **M1 对象基础设施**：SQObject enum（18 类型、位掩码语义）、Rc 对象层、SQStringTable（复刻哈希与 interning）、SQTable/SQArray（复刻物理布局）、SQSharedState（registry/consts/11 张默认委托表/metamethod 名表/RefTable/scratch pad）。
- **M2 词法器**：SQLexer 1:1（关键字表、数字/字符串/verbatim 字符串、`\u` 转义、注释、行号列号）。
- **M3 指令集 + FuncState**：61 条指令枚举与 `#[repr(C)]` 8 字节编码；SQFuncState（寄存器分配、跳转回填、窥孔优化 CMP+JZ→JCMP 等）；SQFunctionProto 等价物（用 `Vec` 分列存储替代 C++ 单块拼接）。
- **M4 编译器**：SQCompiler 1:1 递归下降（全部语法：class/enum/const/static/attributes、lambda、varargs、缺省参数、具名参数块、`::`、base、rawcall、try-catch、generator 函数、绑定环境 `[env]`）。
- **M5 VM 核心**：Execute 主循环（算术/比较/跳转/调用/返回/varargs 打包/缺省参数/异常 trap）、Get/Set 回退链、base 库注册（print/error/compilestring/assert/getstackinfos 等）。**里程碑：hello world 跑通，首轮差分测试开跑**。
- **M6 闭包与 OOP**：outers（GETOUTER/SETOUTER/CLOSE，索引化）、类/实例/单继承/成员两分（field/method）、delegates、18 个 metamethods、weakref、clone、instanceof。
- **M7 生成器与协程**：SQGenerator（Yield/Resume 挂起恢复）、thread（多 VM 共享 SharedState、suspend/wakeup）、GC 环回收 + resurrectunreachable。
- **M8 序列化**：`.cnut` 读写（0xFAFA tag、SQIR 头、字面量/指令编码），验证与官方构建互通（Rust 编译→C++ 加载，反向亦然）。
- **M9 标准库**：sqstdaux（错误钩子/调用栈打印格式逐字复刻）、math、string（format/printf/split/escape…）+ 正则引擎移植（sqstdrex 666 行）、io（file 类/stream 基类/loadfile 的 BOM 与 .cnut 嗅探）、blob、system。
- **M10 CLI**：REPL（花括号续行、行尾 `\` 续行、行首 `=` 改写为 return 并打印、quit()）、命令行参数、脚本参数传递、整数返回值作退出码——全部基于宿主 API 实现，作为引擎库的用法示范。
- **M11 差分强化**：语料扩展至每个语言特性 + HISTORY 中历史 bugfix 的回归用例 + 边角（整型溢出、f32 格式化、深递归栈溢出消息、错误消息文本），修差异至全绿。

## 五、验收标准

1. corpus 全部脚本 stdout 与退出码和原版 sq.exe 一致；
2. samples/ 下 17 个官方示例全部通过；
3. `.cnut` 双向互通验证通过；
4. `cargo test` 全绿；
5. 宿主 API 可用性验证：用 Rust 宿主 API 复刻 etc/minimal.c 的嵌入示例（注册 native 函数 + 调用脚本函数）。

## 六、风险与回退

- 原版编译环境（CMake/MSVC/MinGW）不可用 → 差分降级为预生成期望输出快照；
- f32 格式化与 CRT `%f/%g` 细节差异 → 在 format/print 路径集中适配；
- 语料不足 → 以 doc/ 手册（doc/source，Sphinx rst）语义描述为补充来源编写用例。
